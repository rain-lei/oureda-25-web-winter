# Wordle 程序交互逻辑和生命周期详解

## 1. 程序概述

Wordle是一款基于Web的单词猜测游戏，玩家需要在6次机会内猜出一个5字母的英文单词。每次猜测后，系统会根据字母的匹配情况给出颜色反馈，帮助玩家逐步缩小范围并找到正确答案。

## 2. 程序架构

### 2.1 全局变量定义
```javascript
// 固定的答案长度和最多尝试次数
const answerLength = 5;
const maxGuessTime = 6;

// 颜色编码（使用字母表示）
const grey = "g";    // 字母不存在
const yellow = "y";  // 字母存在但位置不对
const green = "b";   // 字母正确且位置正确

// 游戏状态相关
let answer = "";           // 正确答案
let guess = "";            // 当前猜测
let currentGuessTime = 0;  // 当前尝试次数
let index = 1;             // 当前游标位置（1~30，对应30个网格）
let state = "UNFINISHED";  // 游戏状态：UNFINISHED/SOLVED/FAILED

// 存储数据
let colorSequence = [];    // 颜色序列
let wordSequence = [];     // 单词序列（包括答案和其他可能的单词）
```

### 2.2 HTML结构组件
- **游戏网格**：6行5列的网格，用于显示猜测结果
- **屏幕键盘**：QWERTY布局的虚拟键盘
- **控制按钮**：刷新和显示答案按钮
- **CSS样式类**：用于处理各种颜色反馈

## 3. 程序启动与初始化

### 3.1 程序入口 - start()函数
`start()`函数是程序的唯一入口点，负责：
1. 调用`initialize()`函数初始化游戏
2. 设置各种事件监听器
3. 绑定UI组件与逻辑功能

### 3.2 初始化流程 - initialize()函数
当`initialize()`被调用时，会执行以下步骤：

1. **重置游戏状态**：
   ```javascript
   state = "UNFINISHED";
   currentGuessTime = 0;
   index = 1;
   colorSequence = [];
   wordSequence = [];
   ```

2. **清理游戏界面**：
   - 清空30个网格单元格的内容和样式
   - 重置键盘按键的颜色样式

3. **生成新答案**：
   - 从`words.json`词汇库中随机选择一个单词作为答案
   - 处理词汇库加载失败的异常情况

4. **准备新一轮游戏**：
   - 设置当前索引为第一个单元格（index=1）
   - 准备接收用户输入

## 4. 用户交互处理机制

### 4.1 键盘事件监听
程序通过`document.addEventListener("keydown", ...)`监听键盘事件：

- **字母键**：
  - 检查当前是否允许输入（state !== "UNFINISHED"则不响应）
  - 验证按键是否为有效字母（/^[A-Z]$/）
  - 检查当前行是否未满（index < currentGuessTime * answerLength + answerLength + 1）
  - 添加字母到当前猜测并调用`render()`函数显示

- **回车键**：
  - 验证当前行是否已填满5个字母
  - 调用`handleAnswer()`函数处理猜测
  - 如果提交成功，清空当前猜测（guess = ""）

- **退格键**：
  - 验证是否有字母可以删除（index > currentGuessTime * answerLength + 1）
  - 删除最后一个输入的字母
  - 更新网格显示和猜测字符串

### 4.2 屏幕键盘点击事件
程序通过`querySelectorAll(".key, .longkey")`为所有键盘按钮添加点击事件：

- **字母按钮**：与键盘字母键功能相同
- **Enter按钮**：与键盘回车键功能相同
- **Backspace按钮**：与键盘退格键功能相同

### 4.3 控制按钮功能
- **刷新按钮**：重新调用`initialize()`函数开始新游戏
- **答案显示按钮**：弹出提示框显示当前轮次的答案

## 5. 输入验证与处理

### 5.1 单词验证 - isValidWord()函数
`isValidWord()`函数负责验证用户输入的单词是否有效：

1. **格式验证**：
   - 检查单词长度是否为5个字符
   - 检查是否只包含英文字母（/^[A-Z]{5}$/）

2. **有效性验证**：
   - 检查单词是否存在于词汇库中
   - 如果词汇库为空或未加载，则跳过此检查

3. **返回结果**：
   - 合法单词返回true
   - 不合法单词返回false

### 5.2 答案处理 - handleAnswer()函数
`handleAnswer()`函数处理用户提交的猜测：

1. **预处理**：将猜测转换为大写字母
2. **有效性检查**：调用`isValidWord()`验证单词
3. **计算颜色序列**：调用`calculateColorSequence()`获得匹配结果
4. **更新界面**：
   - 根据颜色序列更新网格单元格样式
   - 更新键盘按钮样式（避免重复标记）
5. **状态判断**：
   - 如果猜中答案：设置state="SOLVED"，显示胜利消息
   - 如果未猜中但还有机会：增加currentGuessTime，准备下一行
   - 如果用完机会：设置state="FAILED"，显示失败消息和正确答案

## 6. 颜色匹配算法

### 6.1 算法核心 - calculateColorSequence()函数
该函数实现Wordle的核心颜色匹配逻辑：

1. **初始化**：创建一个包含5个'g'（灰色）的数组作为初始状态
2. **绿色匹配（正确位置）**：
   - 遍历单词的每个位置
   - 如果猜测字母与答案字母及位置完全相同，标记为'g'（绿色）
   - 将答案中匹配的位置设为空字符串，避免重复匹配
3. **黄色匹配（存在但位置错误）**：
   - 遍历猜测单词中未被标记为绿色的位置
   - 在答案单词中查找相同字母（排除已被标记的位置）
   - 找到则标记为'y'（黄色），并将答案中的该位置设为空字符串
4. **灰色结果**：其余位置保持'g'（灰色）
5. **返回结果**：将数组转换为字符串返回

### 6.2 算法特点
- 处理重复字母的复杂匹配场景
- 确保每个答案字母最多只能与一个猜测字母匹配
- 优先处理绿色匹配，再处理黄色匹配

## 7. 程序状态管理

### 7.1 游戏状态
- **UNFINISHED**：游戏进行中，玩家仍有机会猜测
- **SOLVED**：玩家已猜中答案，游戏胜利
- **FAILED**：玩家用完所有机会仍未猜中，游戏失败

### 7.2 状态转换条件
- UNFINISHED → SOLVED：玩家猜中答案
- UNFINISHED → FAILED：玩家用完6次机会仍未猜中
- SOLVED/FAILED → UNFINISHED：玩家点击刷新按钮开始新游戏

## 8. UI更新机制

### 8.1 网格渲染 - render()函数
- 检查当前行是否还有空位
- 检查游戏是否仍在进行中
- 将字母添加到当前索引对应的网格单元格
- 应用"filled"样式突出显示已填充的单元格
- 更新索引以准备下一个字母

### 8.2 颜色反馈机制
- 根据颜色序列更新网格单元格样式（correct/present/absent）
- 更新对应键盘按键的样式（保持最优反馈）
- 确保相同字母的键盘反馈不被覆盖（绿色 > 黄色 > 灰色）

## 9. 生命周期总结

### 9.1 完整的游戏周期
1. **启动**：程序加载，调用`start()`
2. **初始化**：`initialize()`设置初始状态和界面
3. **交互循环**：接收并处理用户输入
4. **状态判断**：评估猜测结果并更新状态
5. **结束/重置**：游戏结束或开始新游戏

### 9.2 循环中的关键节点
- 每次有效输入都会触发UI更新
- 每次回车提交都会触发答案处理
- 每次状态改变都可能影响后续输入的响应

## 10. 错误处理与边界情况

### 10.1 异常处理
- 词汇库加载失败时使用备用方案
- 界面交互异常的安全检查
- 用户非法操作的预防

### 10.2 边界情况
- 超出输入限制的处理
- 无效输入的忽略
- 游戏结束后的交互禁用
